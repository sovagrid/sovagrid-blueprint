# Обновление VPN-кода на сервере с установленным брокером

Этот контракт относится к **исходникам следующего общего выпуска**. В стабильном
`server-v0.14.1` такое обновление ещё запрещено. Первый шаг — обычная проверка
`POST /api/v1/browser-ssh/vpn-source/preview` с root SSH и независимо проверенным
ключом сервера. Поддерживаются прямой маршрут и один проверенный SSH-хост.

Если требуется обновить управляемый пакет уже установленного брокера, результат
содержит `change:"update"` и `maintenance_required:true`. Поле `expected` сохраняет
четыре прежних SHA-256: манифест источника, установленное дерево, состояние и
кандидат. Непрозрачный `state_sha256` дополнительно связывает точные файлы брокера,
состояния его unit-файлов и отпечатки VPN-данных. Публичный ответ не содержит
ключей, профилей, таблиц клиентов или содержимого закрытого журнала.

Применение требует того же `expected` и отдельного `maintenance:true`.
В панели администратор подтверждает окно обслуживания флажком; обычная кнопка
применения без этого согласия не может остановить существующее управление.
Старый клиент без такого признака получает `CONTROL_ACTIVE`. Проверка роли
повторяется после передачи пакета непосредственно перед применением или
восстановлением. Успешный ответ применения сохраняет прежнюю форму.

Транзакция выполняет следующие действия:

1. Захватывает общий `/run/sovagrid-installation.lock`, затем блокировку VPN-кода
   и точные блокировки установщиков, управления клиентами, маршрутизации и
   создания Amnezia. Незавершённое восстановление хоста блокирует операцию.
   Проверяет CAS заново и запас места на каждом затронутом файловом разделе.
2. Сохраняет закрытый долговечный `maintenance.json` до изменений. Проверяет, что
   существующие launchers/unit-файлы совпадают с предыдущим проверенным пакетом;
   чужие файлы, дополнительные systemd drop-in, незавершённые операции с клиентами
   и неподдерживаемые состояния включения блокируют обновление.
3. Ставит временные фиксированные systemd-ограничения запуска. Их частный
   `maintenance.blocked` сохраняется на диске, поэтому перезагрузка во время
   замены файлов не запускает брокер из неполного пакета. Останавливает только
   сокеты, службы управления и сбор VPN-инвентаря. Контейнер, интерфейс, NAT,
   маршруты и клиентские подключения транзакция не перезапускает.
4. Меняет два проверенных дерева и только ранее установленные файлы брокера.
   Для обычного WireGuard обновляет также точный манифест его установленного
   управления. Проверяет синтаксис, импорт модулей, unit-файлы, затем восстанавливает
   прежнюю активность сокетов/служб/таймера; правила автозапуска не меняются.
5. Проверяет сохранность закрытых VPN-данных, фиксирует результат, удаляет
   временные ограничения запуска и собственные предыдущие деревья.

`vpn-source/recover` восстанавливает прежний код, файлы управления и активность
для незавершённой транзакции; после подтверждённого commit только завершает
очистку. Повторное восстановление безопасно. Если другой администратор изменил
исходники, данные, startup guard или файл управления, восстановление сохраняет
журнал и отказывает до ручного разбора, вместо замены чужого изменения.
`RECOVERY_REQUIRED` после потери связи означает, что сначала нужен этот шаг,
затем новый предпросмотр. `INSUFFICIENT_SPACE` возникает до остановки служб.

Поддерживаются текущие полные семейства файлов Amnezia и обычного WireGuard
(маркер WireGuard схемы 2), без дополнительных systemd drop-in, со состояниями
`enabled`, `disabled` и `static`. Старые или изменённые вручную установки не
принимаются автоматически. Локальные проверки включают ошибки импорта/старта,
конкуренцию, устаревший CAS, сохранность данных и принудительный выход процесса
на этапах замены и commit. Сквозной запуск на одноразовой Ubuntu с настоящим
systemd остаётся обязательной проверкой общего выпуска.
