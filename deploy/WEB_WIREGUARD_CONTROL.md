# Установка управляемого WireGuard на отдельный Agent

Веб-мастер может подготовить root-брокер WireGuard на Ubuntu-сервере, где уже установлен SovaGrid Agent. Сначала используйте действия `vpn-source-preview` и `vpn-source-apply`: они переносят проверенные исходники `sovagrid-vpn` из комплекта Hub на выбранный сервер. Затем `wg-control-preview` показывает состояние установки без изменения удалённого сервера. Отдельная кнопка подтверждения вызывает `wg-control-apply`. Установка включает только root-брокер, его сокет и таймер инвентаризации. Интерфейс WireGuard, VPN-инстанс и клиентские профили она не создаёт и не включает.

Каждый вызов проходит через локальный сокет Web Agent. Шлюз передаёт действующую сессию, а root-сервис заново проверяет неограниченную роль администратора Hub. SSH-соединение использует подтверждённый отпечаток ключа сервера; права root получаются прямым входом или `sudo -n`. Интерактивный запрос пароля sudo не допускается. Вводимый пароль SSH или приватный ключ живут только в памяти запроса и временного SSH-брокера и очищаются после ответа. Пользовательский shell, имя службы, путь к файлу, параметры VPN и произвольная команда не принимаются.

## Контракт root-сокета

Общая форма запроса: `{"action":"wg-control-preview","session_token":"…","payload":{…}}`. `session_token` — текущая сессия Hub, не постоянный токен настройки. Для всех трёх действий `payload` содержит **ровно** `host`, `port`, `username`, `method`, `fingerprint`, `password`, `private_key`, `passphrase` в тех же форматах, что и подготовка Agent. Для `wg-control-apply` дополнительно обязательны `expected:{"state_revision":"<64 hex>","source_revision":"<64 hex>"}` и `confirm:true`. Для `wg-control-recover` дополнительно обязательно `confirm:true`.

Успех сокета имеет вид `{"ok":true,"result":{…}}`. Все результаты содержат `protocol:1`, `scope:"entered_target"`, `host`, `port`, `host_key_fingerprint`. Полный предпросмотр дополнительно содержит `schema_version:1`, `action:"preview"`, `writes:false`, обе ревизии, `installed_current`, `socket_active`, `service_active`, `socket_enabled`, `pending_recovery`, `inventory_timer_active`, `inventory_timer_enabled`, `inventory_snapshot_present`, `missing_dependencies`, `apparmor_profile_present`, `can_apply`, `requires_service_restart` и иногда безопасный код `reason`. Если исходники или состояние ещё нельзя прочесть, сокращённый предпросмотр содержит `can_apply:false`, `pending_recovery` и безопасный `reason` без ревизий; кнопку установки следует отключить.

Успешная установка возвращает `action:"installed"`, `socket_active:true`, `service_active:true`, `inventory_timer_active:true`, `inventory_snapshot_present:true`, `vpn_interface_changed:false`, `source_revision`. Восстановление возвращает `action:"recovered"` и `changed:boolean`. Ошибка сокета имеет вид `{"ok":false,"error":"FIXED_CODE"}`; текст исключения удалённого установщика в браузер не пересылается.

Перед установкой Web Agent повторно получает предпросмотр через новый SSH-вход и сравнивает **обе** ревизии. Root-установщик ещё раз сверяет `state_revision` под блокировкой исходников и состояния перед записью. При `STALE_PREVIEW` нужно заново открыть предпросмотр. При `RECOVERY_REQUIRED` вызывается только явно подтверждённое `wg-control-recover`, после которого предпросмотр повторяется. При `APPLY_UNCERTAIN` или `RECOVERY_UNCERTAIN` повторное изменение вслепую недопустимо: сначала запросите новое состояние. Установка может потребовать системных пакетов: `apt update` и `apt install` ограничены 180 секундами каждый. Шлюз должен ждать ответ до 720 секунд для `wg-control-apply`, до 450 секунд для `wg-control-recover` и до 120 секунд для `wg-control-preview`.

Этот мастер предназначен для прямого SSH-маршрута из Hub до выбранного Agent. Для подключения через промежуточный хост используйте Connect. Обновление уже работающего root-брокера этим действием не выполняется: при необходимости остановить его установщик возвращает `CONTROL_ACTIVE`.
