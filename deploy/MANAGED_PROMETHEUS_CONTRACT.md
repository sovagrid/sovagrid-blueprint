# Установщик управляемого Prometheus

Для управляемой установки Hub SovaGrid. Установка выполняется локально на хосте Hub. Подключение уже работающего источника остаётся отдельным сценарием.

## Мастер

| Запрос | Строгое тело | Строгий ответ |
| --- | --- | --- |
| `POST /api/v1/browser-ssh/managed-monitoring/preview` | `{}` | `{"protocol":1,"action":"preview","state":"absent" \| "ready" \| "needs_reconcile","image_version":"3.16.0","review_sha256":"…"}` |
| `POST /api/v1/browser-ssh/managed-monitoring/apply` | `{"confirm":true,"expected_review_sha256":"…"}` | `{"protocol":1,"action":"applied","state":"ready","image_version":"3.16.0"}` |

Хеши имеют 64 строчных шестнадцатеричных символа. В имеющийся Unix-шлюз запросы передаются как `managed-monitoring-preview` и `managed-monitoring-apply` с той же нагрузкой. Требуется действующий сеанс администратора Hub с доступом ко всем серверам. Предпросмотр связывает состояние проекта, текущий контейнер Hub, проверенный манифест SovaGrid, ревизию конфигурации Hub и закреплённую зависимость. После явного подтверждения хост сверяет план и повторно проверяет полномочия. При расхождении возвращается `STALE_PREVIEW`. Одновременное обслуживание возвращает `BUSY`. Установщик принимает только эти формы. Браузер не передаёт адрес, команду, SSH-доступ, токен или путь.

Ошибки используют существующий формат шлюза. `HUB_UNAVAILABLE` означает, что локальный управляемый Hub не подтверждён. `MONITORING_UNAVAILABLE` означает отсутствие работающего совместимого Prometheus. `MONITORING_UNCERTAIN` требует повторного предпросмотра после частичного применения. Существующие `INVALID_INPUT`, `AUTH_REQUIRED` и `ADMIN_FORBIDDEN` сохраняют значение.

## Запуск и сохранение состояния

Управляемый Prometheus запускается в отдельном проекте Compose со статической конфигурацией. Образ `docker.io/prom/prometheus:v3.16.0` закреплён по digest мультиархитектурного индекса. Prometheus слушает только `127.0.0.1:9090` в сетевом пространстве проверенного контейнера Hub. Он получает измерения только из `127.0.0.1:8765/internal/metrics/prometheus` с отдельным случайным bearer. Значение bearer сохраняется в приватном файле Prometheus. Hub хранит только его SHA-256 через фиксированное локальное действие `monitoring-managed configure` с ревизией. Для браузера подробные графики по-прежнему обслуживает Hub с проверкой прав на каждый сервер.

Повторный запуск переиспользует токен и TSDB, проверяет готовность и успешный скрейпинг. При замене контейнера Hub установщик привязывает проект к новому ID. Предлагается первый запуск через мастер или явный `run.sh --with-prometheus`. История Prometheus считается отдельным производным состоянием. Переносимая копия Hub продолжает сохранять исходные метрики и настройки Hub. На новом хосте для управляемого источника нужно повторно запустить мастер.
