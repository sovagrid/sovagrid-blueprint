# Настройка отдельного допуска терминала через Web

Предложение дополняет [действующий мастер Agent](WEB_AGENT_FEATURES.md) для серверов, зарегистрированных мастером SSH. Начало работы, проверка отпечатка, учётные данные, выбор сервера и подтверждение плана остаются общими. Новый режим сохраняет настройки очереди команд и файлов на Agent и в Hub.

## Браузер и шлюз

- Сохраняются `POST /api/v1/browser-ssh/agent-features/preview` и `POST /api/v1/browser-ssh/agent-features/apply`. Запросы общего режима остаются без изменений.
- В режиме терминала стандартное тело SSH запроса дополняют `server_id`, `permission: "terminal"` и `terminal_enabled`. Ключ `features` в этом режиме запрещён. Для чтения `terminal_enabled: null`, для плана и применения тип строго `boolean`. Применение требует те же `expected_review_sha256` и `confirm: true`. Unix-сокет принимает прежние действия `agent-features-preview` и `agent-features-apply` с таким же различением полезной нагрузки.
- К существующим полям ответа добавляются только `permission: "terminal"` и `terminal_access: {enabled: boolean, mode: "legacy" | "explicit"}`. `hub_enabled` остаётся значением допуска команд. `current`, `desired` и ненулевой `pending_features` сохраняют три булевых поля `commands`, `terminal`, `files`. Файлы требуют локального допуска команд. Режим терминала допускает `terminal:true` при `commands:false`. Успех применения требует `terminal_access.mode === "explicit"`, `terminal_access.enabled === desired.terminal`, `current === desired` по значениям, свежую метрику и подтверждённую очистку. Каждый успешно распознанный ответ должен соответствовать режиму запроса. Прежний обработчик общего режима остаётся строгим.
- `TERMINAL_PERMISSION_UNAVAILABLE` означает, что Hub не поддерживает запись отдельного допуска. Старый Hub может вернуть 404 для нового маршрута, а пока проверка обновления и восстановления блокирует запись, новый Hub возвращает 503. Пропавшая регистрация и смена поколения токена по-прежнему делают план недействительным.

## Применение в Blueprint

Blueprint читает `/api/v1/servers/{id}/agent-management/permissions` с сессией администратора Hub и закрепляет ревизию, регистрацию и поколение токена вместе с состоянием SSH-цели и пакета. После ручного подтверждения повторно читает эти данные. Затем CAS закрепляет запрет PTY на Hub и оставляет допуск команд прежним. Так отключаются активные PTY на время применения, а восстановление прерванного плана не теряет настройки очереди и файлов. Для наследуемой политики этот шаг является явным переключением политики с временным запретом PTY. Операция в целом сохраняет оба прежних разрешения команд (локальное и Hub), включая их различие при предварительной настройке. Только после новой метрики, повторной проверки режима, конфигурации и готовности обоих ресурсов PTY, очистки и закрытия SSH новый CAS выставляет выбранный допуск. Повтор после неопределённого результата начинается с нового чтения и просмотра плана.

## Внутренний staged RPC

Имена `target-features-{status,preview,apply}` и номер протокола оболочки сохраняются. Новый строгий вариант каждого запроса добавляет `permission: "terminal"`. `features` в preview/apply сохраняет прежний набор полей, но допускает терминал при выключенных командах. Только ответы этого варианта добавляют `terminal_mode: "legacy" | "explicit"`, который указывает на текущий локальный режим Agent. Успешный apply подтверждает explicit. Режим входит в фактическое состояние CAS и проверку перед повторным открытием доступа. Обработчик на цели отвергает попытку нового варианта изменить локальные команды или файлы. Старый вариант отвергает управление явно настроенным Agent, пока не умеет сохранять самостоятельный допуск. Незавершённый план старого варианта нужно завершить в прежнем мастере, а план нового варианта восстанавливается новым.
