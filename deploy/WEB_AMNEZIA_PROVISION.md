# Установка AmneziaWG на другом Ubuntu-сервере

Web Agent принимает три операции: `amnezia-provision-preview`, `amnezia-provision-apply` и `amnezia-provision-recover`. Это отдельный opt-in шаг после установки Agent и подготовки проверенного VPN-кода на выбранном сервере. Он создаёт только новый контейнер `amnezia-awg2`; чужой контейнер не заменяется. Установка использует закреплённый образ AmneziaWG и проверяет работающий `awg0` через существующий модуль управления. Новых клиентских профилей этот шаг не создаёт.

Все запросы требуют действующего сеанса администратора Hub с полным доступом, точного отпечатка SSH-ключа хоста и root либо `sudo -n`. Восьми полям SSH-входа (`host`, `port`, `username`, `method`, `fingerprint`, `password`, `private_key`, `passphrase`) соответствуют те же ограничения, что в мастере Agent. Пароль и приватный ключ стираются из словаря запроса после операции. Имя `port` означает SSH-порт, а `listen_port` — UDP-порт VPN.

| Операция | Дополнительные поля | Результат |
| --- | --- | --- |
| `preview` | `listen_port` (1–65535), `subnet` (каноническая частная IPv4 `/24`), `route_mode` (`full`/`split`) | Предпросмотр без записи: состояние, SHA-256 ревизия, digest закреплённого образа и точная причина отказа. |
| `apply` | Те же поля, `expected_state` (64 строчных hex), `confirm: true` | Повторный предпросмотр и CAS-проверка ревизии; запуск только собственного контейнера и проверка интерфейса. |
| `recover` | `confirm: true` | Проверка или откат только собственного незавершённого состояния. |

`full` настраивает NAT для выхода клиентов в интернет. `split` даёт доступ только к подсети сервера и должен быть выбран явно. Полный режим отказывает, если маршрутизация не запускается. Предпросмотр проверяет занятость UDP-порта, но Docker повторно проверяет её при запуске.

Публичный ответ ограничен `{protocol:1, scope:"entered_target", host, port, host_key_fingerprint, ...}` и фиксированными полями результата CLI. Приватные ключи сервера, конфигурация `awg0`, Docker stderr и произвольный текст удалённого сервера в Web не возвращаются. При потере связи после начала изменения возвращается `APPLY_UNCERTAIN` или `RECOVERY_UNCERTAIN`: клиент должен заново проверить сервер и при необходимости вызвать `recover`, а не повторять `apply` вслепую. Предпросмотр CLI занимает до 30 секунд, установка до 300, восстановление до 60; с SSH-проверкой и CAS суммарные бюджеты сокета Web составляют 120/480/180 секунд.

Путь исполняемой программы фиксирован: `/bin/sh /opt/sovagrid-src/sovagrid-vpn/deploy/sovagrid-amnezia-provision`. Запуск через `/bin/sh` необходим для удалённого Agent-only хоста: проверенный установщик VPN-кода сохраняет исходники с правами `0644`. Мост проверяет владельца root и отсутствие записи группой/другими у каталога исходников и файла установщика, а также ограничивает успешные поля и коды отказа. Клиент не передаёт путь, команду, имя контейнера или образ.

Локальная совместимость собранного контейнера проверена в одноразовом Docker-стенде с `split`; полный NAT и сквозное VPN-подключение ещё требуют одноразового Ubuntu-хоста. До такой проверки этот шаг нельзя считать подтверждённой установкой полного VPN на всех поддерживаемых Ubuntu.
