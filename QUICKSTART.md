# Быстрый запуск SovaGrid на Ubuntu

## Одна команда на пустом сервере

Подключитесь к своему серверу с Ubuntu 22.04, 24.04 или 26.04 по SSH и выполните:

```sh
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/sovagrid/sovagrid-blueprint/main/bootstrap/run.sh | sudo bash'
```

Скрипт спросит путь панели (по умолчанию `/sovagrid/monitoring/`) и, при желании, публичный домен или статический IPv4. Корень сайта `/` по умолчанию не меняется. Затем он скачает ровно [проверенный серверный выпуск v0.13.0](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v0.13.0), сверит SHA-256 архива и манифеста, поставит Docker/Compose и зависимости через включённый в выпуск `run.sh`, запустит Hub, Web и Agent, включит терминал, файловый раздел, инвентаризацию контейнеров и управление WireGuard. Если на сервере есть `ssh.service`, откроется чтение его последних записей журнала. Выпуск содержит только исходники; пароль создаётся уже на вашем сервере и показывается только в текущем терминале. Имя администратора — `admin`.

Для публичного HTTPS адрес должен заранее указывать на этот сервер, а TCP-порты 80 и 443 должны быть доступны. Если публичный адрес пока не готов, оставьте поле пустым: панель откроется через SSH из приложения или Connect. Путь и публичный доступ можно изменить позже в разделе Web панели. Токен Telegram вводится в разделе Telegram; вручную создавать файлы с секретами не требуется. Повторный запуск этой команды не перезаписывает существующую установку — обновление выполняется в панели или Connect.

## Без консоли на новом сервере

Откройте приложение [SovaGrid Connect](https://github.com/sovagrid/sovagrid-connect) для macOS, Windows или Linux. Укажите адрес нового Ubuntu-сервера и SSH-пользователя `root`; ключ или пароль и отпечаток SSH-хоста приложение запросит в отдельных окнах. Нажмите **«Подключиться»**: Connect проверит состояние сервера и предложит установить проверенный серверный пакет из Starter, если сервер пуст. После установки он откроет панель выбранного сервера. На обновлённом Hub root/sudo SSH-доступ выдаёт одноразовый вход без отдельного ввода пароля Hub; на более старом Hub остаётся обычный местный логин. Если хотите заранее выбрать WireGuard, терминал, файлы или журналы, откройте «Установить на сервер…»; для журналов впишите точные имена `.service`, по одному в строке. Токен GitHub и команды в терминале не нужны.

Это действие предназначено для первой установки на пустой Ubuntu-сервер с root SSH-доступом. Узел, где уже работает только удалённый Agent, распознаётся отдельно: автоматическая установка Hub не трогает его ключи, токен и обратный туннель. Конфликтная частичная установка тоже не перезаписывается. Для включения дополнительных функций откройте «Включить функции…»: Connect проверит работающую установку и исходники, покажет текущие функции и после подтверждения запустит её `run.sh`. Выбранный список журналов целиком заменит прежний; обычное включение другой функции список не затронет. Для обновления действующей версии откройте «Обновить сервер…»: сначала подготовьте проверенный пакет, затем выберите немедленное применение или разовое применение при простое, пока Connect открыт. Connect сохраняет управляемое состояние и проверяет откат при ошибке; ограничения описаны в [DEPLOY.md](DEPLOY.md). Пакет выбирайте из доверенного источника: проверка манифеста обнаруживает повреждения, но не доказывает, кто его создал.

## Добавить другие серверы

После первой установки Hub откройте в Connect **«Добавить другой сервер…»**. Укажите адрес и SSH-доступ нового Ubuntu-сервера, а также адрес вашего Hub, доступный с него. Connect проверит SSH-ключи, покажет план и после вашего подтверждения установит на новом сервере только Agent и зарегистрирует его в вашем Hub. Токен Agent и ключ постоянного соединения создаются автоматически; вводить их в консоли не нужно. Серверы могут находиться в разных сетях и странах, если между ними настроен нужный SSH-маршрут. Веб-мастер добавления серверов пока находится в разработке; уже установленные серверы доступны в общей веб-панели.

## Ручная установка и обслуживание

Для ручной установки на свой Ubuntu-сервер склонируйте пять публичных репозиториев рядом. Установщик не содержит заранее заданного сервера или общей учётной записи:

```sh
sudo apt-get update
sudo apt-get install -y git
sudo install -d -o root -g root -m 0755 /opt/sovagrid-src
cd /opt/sovagrid-src
sudo git clone https://github.com/sovagrid/sovagrid-blueprint.git
sudo git clone https://github.com/sovagrid/sovagrid-hub.git
sudo git clone https://github.com/sovagrid/sovagrid-web.git
sudo git clone https://github.com/sovagrid/sovagrid-agent.git
sudo git clone https://github.com/sovagrid/sovagrid-vpn.git
```

Итоговое расположение:

```text
/opt/sovagrid-src/
  sovagrid-blueprint/
  sovagrid-hub/
  sovagrid-web/
  sovagrid-agent/
  sovagrid-vpn/
```

Для установки без клонирования GitHub-репозиториев скачайте [проверенный серверный пакет v0.13.0](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v0.13.0) и сверьте SHA-256 со значением в [DEPLOY.md](DEPLOY.md). Передайте `SovaGrid-server-source.tar.gz` на сервер через доверенный SFTP-клиент и распакуйте от root в `/opt/sovagrid-src`: `sudo install -d -o root -g root -m 0755 /opt/sovagrid-src && sudo tar -xzf SovaGrid-server-source.tar.gz -C /opt/sovagrid-src`. При самостоятельной сборке пакета из пяти репозиториев запустите на доверенном компьютере `python3 sovagrid-blueprint/package_server.py`. Упаковщик берёт только уже сохранённые в Git файлы и не кладёт в архив локальные пароли, базу, `.git` и кеши. На сервере для установки не нужен GitHub-токен.

Затем запустите:

```sh
cd /opt/sovagrid-src/sovagrid-blueprint
sudo ./run.sh
```

Для возможности управлять **отдельным стандартным WireGuard** из панели выберите WireGuard при первой установке или «Включить функции…» в Connect позже. Ручной эквивалент: `sudo ./run.sh --with-wireguard`. В этой быстрой установке Hub и Agent находятся на одной машине; опция не создаёт VPN и не меняет существующую Amnezia. Если выбран другой Agent, брокер должен быть установлен также на его Ubuntu-хосте; `run.sh` не разворачивает компоненты на удалённые машины. Команды экспорта клиентского профиля и восстановления операций приведены в [sovagrid-vpn](https://github.com/sovagrid/sovagrid-vpn).

В панели выберите сервер с подключённым Agent и разрешёнными командами. После отдельного подтверждения можно подготовить WireGuard-инстанс, запустить его, добавить или отозвать клиента и удалить инстанс; удаление дополнительно требует ввода его точного имени. Создание не запускает интерфейс. Результат виден в заданиях, а сводку обновляет таймер примерно раз в 30 секунд. Эта сводка показывает только хост Hub, даже если выбран другой Agent. Amnezia доступна в панели для подробного просмотра состояния протоколов, клиентов и трафика; отдельные кнопки управления профилями AmneziaWG включаются лишь после ручной подготовки целевого хоста по [инструкции VPN](https://github.com/sovagrid/sovagrid-vpn/blob/main/AMNEZIA_ADMIN.md). Для получения клиентского WireGuard-профиля в панели нажмите «Запросить защищённый профиль», затем «Скачать .conf» в той же вкладке; файл шифруется до Agent и Hub, а расшифровывается только на вашем устройстве. Нативные приложения открывают системное сохранение файла. Root-only `export-client` остаётся резервным способом.

Для интерактивного терминала выберите его при первой установке или «Включить функции…» в Connect позже; ручной эквивалент — `sudo ./run.sh --with-terminal` на Ubuntu-хосте с Agent. В Hub разрешите команды для нужного сервера. Терминал запускается от отдельного пользователя `sovagrid-shell`; он не имеет доступа к токену Agent. Ввод и вывод терминала не хранятся в аудите. Подробности — в [DEPLOY.md](DEPLOY.md).

Для текстового файлового менеджера выберите его при первой установке или «Включить функции…» в Connect позже; ручной эквивалент — `sudo ./run.sh --with-files`. Скрипт создаст приватный каталог `/var/lib/sovagrid-agent/files` и разрешит Agent работу только с ним. В Hub разрешите команды для выбранного сервера, затем откройте раздел «Файлы». Чтение и запись других путей требуют отдельного явного списка `file_roots` на соответствующем Agent; детали — в [DEPLOY.md](DEPLOY.md).

Для последних строк журнала службы выберите функцию в Connect и укажите 1–16 точных имён `.service`; ручной эквивалент — `sudo ./run.sh --with-journal --journal-unit ssh.service`. Скрипт установит отдельный read-only broker, который перепроверяет список; пользователь Agent не получает общий доступ к журналам ОС. В Hub также разрешите удалённые команды для сервера. В панели будут доступны только выбранные службы. Установщик сохраняет разрешение при обычном повторном запуске. Для полного выключения выберите «Полностью выключить журналы» в Connect; консольный эквивалент — `sudo ./run.sh --disable-journal`. Подробности — в [DEPLOY.md](DEPLOY.md).

`run.sh` использует установленные Docker и Compose или устанавливает недостающие пакеты из настроенных Ubuntu-репозиториев. Он запускает Hub и веб-панель в отдельном Docker Compose-проекте, а Agent — как непривилегированную службу systemd на Ubuntu, чтобы метрики относились к самому серверу. Пароль администратора создаётся автоматически в `/etc/sovagrid/admin-password` с доступом только root. Имя пользователя для входа в Hub: `admin`. После первого входа пароль можно сменить в разделе «Настройки»; старые сеансы завершатся. Исходный файл с начальным паролем при этом не изменится.

Панель на тестовом сервере доступна через SSH-туннель:

```sh
ssh -L 8766:127.0.0.1:8766 SSH_USER@SERVER_ADDRESS
```

Откройте `http://127.0.0.1:8766/sovagrid/monitoring/` на своём компьютере через SSH-туннель. На iPhone или Android добавьте **свой** сервер как SSH-профиль и выберите открытие панели через SSH: приложение создаст временный проброс само. Для macOS, Linux и Windows [SovaGrid Connect](https://github.com/sovagrid/sovagrid-connect) поднимет такой же проброс и откроет полную панель в браузере. Пароль, парольную фразу ключа и отпечаток SSH-хоста приложение запрашивает в графических окнах; изменившийся ключ отклоняется. Если сервер доступен через промежуточный SSH-хост, задайте его отдельные реквизиты в профиле. Внутренние порты панели опубликованы только на loopback сервера. Публичный HTTPS по собственному IP или домену задаётся при однокомандной установке либо позже в Connect/Web; Agent использует локальный HTTPS с собственным CA.

На обновлённом Hub вход через root/sudo SSH даёт местный сеанс администратора без повторного ввода пароля Hub. Одноразовый пропуск действует 60 секунд, передаётся по SSH и погашается в выбранной панели; он не сохраняется в профиле и не попадает в URL. Для входа прямо по публичному HTTPS или со старым клиентом используйте логин и пароль **этого** Hub. Первый пароль можно получить кнопкой «Получить начальный пароль» в приложении или «Получить начальный пароль по SSH» в Connect, если SSH-пользователь имеет право чтения файла (обычно `root`). После смены пароля в «Настройках» исходный файл устаревает.

Для Telegram-бота откройте раздел «Telegram» в панели администратора и вставьте токен BotFather. Перезапуск `run.sh` для этого не нужен. Откройте своего бота в Telegram и отправьте `/start` или `/connect`; в панели появится заявка. Проверьте, кто её отправил, выберите роль `viewer`, `operator` или `admin` и подтвердите. Числовые ID и консоль для обычной привязки не нужны. Привязанные пользователи могут получить сводку VPN командой `/vpn`; произвольные команды требуют отдельного разрешения в Hub и Agent и подтверждения администратором. Старый root-owned файл `/etc/sovagrid-hub/bot.token` также поддерживается как внешняя настройка. Тревоги и восстановление сохраняются в очереди Hub, если Telegram временно недоступен; в панели видно число ожидающих уведомлений. После восстановления отправка повторяется, а при неопределённом HTTP-ответе возможен дубль. Подробности — в [DEPLOY.md](DEPLOY.md).

В разделе «Настройки» задайте пороги тревог по CPU, памяти, диску, время отсутствия связи и задержку подтверждения проблемы в минутах. При задержке 0 тревога появляется сразу; краткий всплеск при ненулевой задержке не создаёт инцидент. Сохранение действует при следующем измерении или проверке связи и не требует перезапуска. Если правила в это время изменили в другой вкладке, панель попросит загрузить свежие значения перед повторным сохранением.

После входа раздел «Начало» показывает, какие функции уже работают и что настроить дальше. В обзоре сервера есть последние десять процессов по используемой памяти; имена команд, параметры и переменные окружения в этот список не входят, история процессов не сохраняется. В терминале телефона доступно отдельное поле для ввода или вставки одной строки и кнопка отправки; поле очищается после отправки и закрытия терминала.

Apple-клиент открывается в Xcode, Android-клиент — в Android Studio; веб-панель работает в браузере. SSH-пароль относится к пользователю Ubuntu, а пароль Hub — к учётной записи SovaGrid. Для прямого SSH с телефона нужен доступ к порту SSH выбранного сервера. Для сервера за промежуточным SSH-хостом задайте отдельные адреса, пользователей и ключи; порядок полей описан в [DEPLOY.md](DEPLOY.md).

При полном отключении машины размещённый на ней Hub не сможет отправить уведомление. Для этого нужен внешний наблюдатель. Реализованные функции и следующие этапы описаны в [ARCHITECTURE.md](ARCHITECTURE.md), [ROADMAP.md](ROADMAP.md) и README отдельных репозиториев.

## Создать SSH-ключ без подключения

В Apple откройте «SSH → SSH-ключи», в Android — «SSH-ключи». Задайте имя, создайте ключ и нажмите «Скопировать открытый ключ». Добавьте скопированную строку в SSH-доступы сервера через панель провайдера или администратора. Затем выберите ключ из «Моих ключей» в профиле подключения. Приватная часть остаётся в Keychain/Android Keystore; отдельные ключи можно выбрать для сервера и промежуточного SSH-хоста. Создание ключа само не меняет сервер и не заменяет первый вход.

В Connect рядом с полем ключа нажмите «Создать…», выберите новый файл и задайте парольную фразу в скрытых окнах OpenSSH. После создания приложение покажет открытую часть и отпечаток, а путь подставит в профиль. Существующий файл не перезаписывается. Если вы переносите файл в текущий Apple-клиент, он поддерживает импорт незашифрованного Ed25519: вариант без парольной фразы в Connect выбирается явно. Для обычного создания ключа на телефоне перенос файлов не нужен.

## Проверить сайт или порт

После обновления Hub, Agent и панели откройте обзор сервера → «Сетевые проверки» → «Добавить проверку». Выберите HTTP/HTTPS или TCP, введите название и цель, интервал и тайм-аут. Для сайта укажите конечную страницу без учётных данных и параметров: перенаправления не выполняются, успехом считается HTTP 2xx. Для TCP укажите отдельный хост и порт.

Проверку выполняет выбранный Agent, поэтому `127.0.0.1` относится к его серверу, а не телефону. Без добавленных целей соединения не выполняются. Изменять и удалять цели может администратор; историю и результаты видят все роли, адреса целей наблюдателям не выдаются. «Проверить сейчас» запрашивает ближайший свободный worker. HTTPS показывает срок проверенного сертификата и предупреждает за 14 дней; TCP сообщает только об установлении соединения. Потеря связи с Agent показывает давность результата. Инциденты проверок отправляются в Telegram по общим правилам уведомлений; отдельное предупреждение об истечении TLS-сертификата включается в настройках HTTPS-проверки.

Требуются совместимые версии Hub, Agent и веб-панели с checks protocol 1. Новую версию можно выбрать в Connect через «Обновить сервер…» с проверкой SHA-256 и откатом при ошибке.
