# Проверка архива хоста и план восстановления

`deploy/host_restore.py` проверяет закрытый архив, созданный `deploy/host_backup.py`, и сравнивает его с текущим Ubuntu-хостом. Это **операция только для чтения**: команды извлечения и применения архива пока нет. Проверка не останавливает службы, не обращается к сети и не меняет файлы хоста.

Запускать установленную копию через проверенный root SSH-доступ:

```text
python3 -I /opt/sovagrid-src/sovagrid-blueprint/deploy/host_restore.py verify <32-hex-id>
python3 -I /opt/sovagrid-src/sovagrid-blueprint/deploy/host_restore.py plan <32-hex-id>
```

В ответе — одна строка JSON. При успехе exit `0`, `ok:true`, `protocol:"sovagrid-host-restore-plan-v1"`, `verified:true`, краткая запись архива и digest source manifest. `verify` также сообщает число записей, суммарный размер прочитанных несжатых файлов и количество разрешённых файлов Python bytecode. Он не выводит содержимое архива или имена секретов. При отказе — exit `40` с `ok:false` и кодом `error`. Нужен root; архив и манифест остаются в каталоге `/var/lib/sovagrid-host-backups` с правами `root:root 0600`.

`plan` сначала делает полную проверку архива, затем читает layout текущего хоста (`full` либо `hub-only`), digest установленного `/opt/sovagrid-src`, активные writer units и состав работающих Compose-контейнеров. Поля `same_layout` и `same_source` показывают совпадение; `target_running_containers` допускает пустой список, пару `hub`/`web` для установок 0.6 либо тройку с необязательным `ssh-gateway`. `blockers` всегда содержит `APPLY_NOT_IMPLEMENTED`; при различии добавляются `LAYOUT_MISMATCH` и `SOURCE_MISMATCH`, а при неполном составе Hub/Web — `TARGET_STACK_DEGRADED`. `apply_available` всегда `false`. План может устареть после следующего обновления или изменения хоста.

## Что проверяется

- Закрытый каталог и файлы архива, root-владелец, права `0600`, один hardlink и размер; SHA-256 сжатого tar сверяется с манифестом. Изменение открытого файла между хешированием и чтением обнаруживается по метаданным файлового дескриптора.
- Манифест должен иметь формат `sovagrid-host-backup-v1`, валидный ID, layout, размер, число записей и digest установленного source bundle. Старые архивы без `source_manifest_sha256` получают `SOURCE_UNPINNED`.
- Каждая tar-запись должна быть обычным файлом или каталогом в разрешённом корне SovaGrid. Запрещены абсолютные пути, `..`, повторы, symlink, hardlink, устройства и пропуск либо перестановка родительских каталогов. Проверяются UID/GID, режим, размер и обязательные файлы каждого layout. Для каталогов с закрытым набором файлов используется тот же список, что у создателя архива. Если есть marker управляемого SSH gateway, дополнительно проверяются его точное содержимое и права; для архивов 0.6 он необязателен.
- Встроенный `sovagrid-bundle.json` должен совпасть со своим pinned SHA-256 и точной картой файлов пяти исходных репозиториев. Каждый файл перечитывается и сверяется с digest; лишние файлы и каталоги отвергаются. Разрешён только формат сгенерированного Python bytecode, который признаёт установленный updater.
- Применяются лимиты создателя архива: 20 000 записей, 8 GiB суммарного содержимого и 4 GiB на файл; чтение ограничено по времени. `verify` не извлекает данные на диск.

Текущий создатель архива безусловно требует базу Hub и локальные Caddy `root.crt`/`root.key` также при публичном адресе. Проверяющий следует этому контракту. Список допустимых unit-файлов берётся из установленного updater; архив другой версии может не пройти проверку на обновлённом хосте.

## Почему нет применения

Проверка содержимого не решает согласованную остановку всех writers, восстановление SQLite, Caddy/VPN state, соответствие Docker images Hub/Web/SSH gateway установленным исходникам, долговечный журнал операции, атомарное переключение и откат после сбоя. До проверки этих свойств в отдельном изолированном стенде `host_restore.py` намеренно не предоставляет `apply`/`recover`; успешный `verify` не означает, что архив уже можно безопасно развернуть. Gateway не имеет собственного persistent volume. Внешний Agent и домашний SSH-туннель не входят в этот архив и должны рассматриваться отдельно.
