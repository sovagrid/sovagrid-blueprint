# Подготовка SovaGrid 1.0.0

Готовится единый серверный и клиентский выпуск. Опубликованный стабильный сервер остаётся [server-v0.14.1](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v0.14.1); основные ветки и подготовленные номера версий ещё не являются выпуском 1.0.0. Серверные URL и хеши клиентов пока указывают на 0.14.1.

Публикация в App Store и Google Play не требуется: Android распространяется APK с прежней подписью, Connect — сборками для компьютеров, Apple — проектом для установки через Xcode и сборкой для macOS. Для личного iPhone можно использовать обычный Apple ID в Xcode. Установка на физический телефон не подменяется проверкой симулятора.

## Текущий статус проверки

В текущих исходниках `APPLY_ENABLED=True`. На отдельной Ubuntu с обычным запасом диска проверены реальная гибель процесса и откат, независимое применение всех 114 шагов с запуском Hub/Agent/Web/команд/файлов/PTY, позднее переподключение с прежним CAS/nonce и сохранение изменившейся SQLite при ошибке здоровья. На Ubuntu amd64 общий gate также подтвердил первое переподключение во время работы нового публичного worker; весь gate пока не завершён из-за проверки состава тестовой установки после штатной очистки старого служебного архива. Это включение исходников, а не публикация нового архива. Клиент использует capability своего проверенного runner.

## Сценарии и условия готовности

| Сценарий | Условие выпуска |
| --- | --- |
| Первый сервер | Одна команда или SSH из приложения устанавливает зависимости, Hub, Web и Agent. Терминал, файлы и мониторинг контейнеров доступны после проверки. Выбор публичного IPv4 или домена объяснён до ввода; путь панели и поведение корня настраиваются. |
| Подключение | Пароль, импортированный или созданный клиентом SSH-ключ; проверка ключа сервера; прямой маршрут и один промежуточный SSH-хост. Публичный ключ можно скопировать до подключения. |
| Дополнительные серверы | Connect и веб-мастер устанавливают Agent на другой Ubuntu с планом и подтверждением; после обрыва операция открывается по прежнему ID. |
| Панель на телефоне | Терминал, команды, файлы, мониторинг и настройки доступны через панель. Apple/Android поддерживают системный выбор и сохранение файлов, порционное чтение архива восстановления. Светлая/тёмная тема следует устройству или выбору пользователя; Web поддерживает PWA. |
| Права и Telegram | Локальные аккаунты, роли и права на серверы, ограниченные действия и аудит. Токен бота вводится через UI; команды проверяют роль и подтверждение. |
| VPN | WireGuard и поддерживаемый AmneziaWG: управление клиентами, защищённая выдача профилей, проверенные SSH-маршруты. Обслуживание VPN-кода сохраняет конфигурацию и клиентов. Состояние сквозных проверок Web указывается отдельно. |
| Обновление | Подписка включается явно; занятый сервер откладывает замену, ошибочный кандидат откатывается. Full 0.14.1 обновляется установленным старым подписанным updater; Hub-only 0.14.1 сначала проходит разовый ручной переход. |
| Резервная копия | Пять согласованных файлов скачиваются через UI. Применение поддерживаемой копии v2 полного layout на чистой Ubuntu восстанавливает образы, данные, учётные записи, права и службы. Проверки должны подтвердить прерывание, откат и сохранение изменившихся данных. |
| Поставка | Все клиенты закрепляют один проверенный серверный архив и его манифест. Версии, контрольные суммы и инструкции согласованы; публичные материалы используют общие примеры. |

## Что уже подтверждено

- [Full 0.14.1 → новый согласованный кандидат](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41298983265): проверены повреждённая подпись, занятый сервер, настоящее применение в простое и откат намеренно ошибочного кандидата. Работали установленные feed/auto/worker опубликованной 0.14.1; ключ подписи в тесте одноразовый.
- [Hub-only 0.14.1 → ручной переход → следующее подписанное обновление](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41298989964): подтверждены откат, работа broker sandbox и сохранность внешнего Agent и SSH-транспортов.
- [Общий интеграционный прогон](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41329968469) подтвердил зависимости восстановления без SovaGrid-служб, повторный bootstrap и двоичную передачу, обслуживание VPN-службы с перезапуском, полную установку, Hub/Web/Agent, watchdog, дополнительные Ubuntu через Connect и Web, подписанное обновление, аварийный откат и настоящее переносимое применение с переподключением во время работы. Весь запуск пока не завершён: проверка восстановленной тестовой установки ошибочно требует старый служебный архив, который Web штатно удаляет. Проверка исправляется отдельно от рабочего кода.
- Последние полные локальные наборы прошли: Blueprint 949 тестов (21 пропущен по окружению), Connect 518 (32 пропущено), Web 388 и gateway 79. Веб-мастер восстановления прошёл браузерную проверку на ширине компьютера и телефона, включая повтор выбора файлов, отмену и план с выключенным применением.
- Реальная локальная цепочка Core → Web-журнал → gateway проверила политику raw6 → public4 и неизменный review SHA. Семь реальных экспортов Docker 28.5.2/29.5.2 подтвердили форматы образов и привязку config/RootFS/platform.
- Web-мастер прав Agent проверен по настоящему HTTP/SSH-маршруту через промежуточный хост: просмотр, план, подтверждение, команды/терминал/файлы и закрытая политика до завершения очистки. WireGuard прошёл всю цепочку Web → Agent → брокер → защищённый профиль → настоящий kernel handshake и двусторонний обмен пакетами. Эти результаты не обозначают новую полную Web-проверку автоматической установки AmneziaWG на amd64; ARM64 явно отказывает в таком сценарии.
- iPhone Simulator и Android API 30/36 проверили системный выбор и сохранение файлов. Отдельный механизм восстановления прочитал настоящий архив более 8 МиБ порциями с проверкой хешей. Сборки Apple и Android подготовлены; номера проектов — Apple 1.0.0/build 16 и Android 1.0.0/code 17. Это не опубликованные клиентские релизы.

## Ограничения восстановления

В исходниках реализованы независимый закреплённый исполнитель, подготовка зависимостей, приём пяти файлов, закрытая стадия, план, применение, карантин очереди, проверка здоровья, откат, восстановление и повтор. `backend_supported` обозначает capability runner, `target_ready` — физическую готовность, `apply_available` — их совместное разрешение. Свежий `apply_review_sha256` связывает capability, политику, ресурсы и ревизию попытки. Наличие мастера в UI не включает применение на старом сервере или в неподтверждённом исполнителе; текущий флаг указан выше.

Поддерживаемая цель — чистая Ubuntu с systemd, root SSH или уже настроенным sudo без запроса пароля. План учитывает дополнительные 8 ГиБ для ограниченного подтверждения образов при смене Docker storage format; одного совпадения RootFS недостаточно, Compose получает immutable ID из проверенного config/manifest/index графа. Нужна квитанция v2 и полный layout. Hub-only, квитанция v1, активное состояние VPN-маршрутизации, неподдерживаемые файловые корни и изменение публичного адреса блокируют применение до подтверждения. Ожидающие команды и Telegram-подтверждения из копии отменяются; поддерживаемые VPN-интерфейсы после переноса остаются выключенными.

**Полное переносимое восстановление AmneziaWG не поддерживается.** Архив хоста включает журналы установки, но не актуальные конфигурацию и таблицу клиентов внутри Docker-контейнера; AWG-образ также не входит в экспорт. План отказывает с `VPN_PORT_UNVERIFIED`. До реализации согласованного снимка и восстановления контейнера этот сценарий нельзя обозначать как полный backup рабочих VPN-данных.

При переносе Hub строки внешних Agent в базе сохраняются, но Hub-side SSH-транспорты, их аккаунты и системные SSH host keys Ubuntu не входят в архив. Удалённые серверы нужно переподключить через мастер; проверка локального восстановления не является проверкой их автоматического переноса.

Контракты: [мастер Web/PWA](deploy/WEB_PORTABLE_RESTORE.md), [исполнитель на цели](deploy/PORTABLE_RESTORE_TARGET.md), [резервные копии хоста](HOST_BACKUP.md).

## Оставшиеся условия публикации

1. Завершить общий интеграционный gate публичного worker, после исправления проверки состава тестовой установки. Первое переподключение во время активного восстановления уже прошло на amd64, три реальных Ubuntu-сценария — локально; проверки транзакционных границ не означают аварийного теста VM после каждой фазы.
2. Сформировать окончательный серверный архив и манифест; синхронизировать URL и оба SHA-256 в bootstrap и всех клиентах.
3. Собрать общие поставки Connect, Android APK с существующим ключом подписи, Apple-проект и macOS-приложение; проверить соответствие версий и опубликованных файлов.
4. Опубликовать один общий серверный выпуск 1.0.0 и подписанный переход после завершения проверок. Промежуточные коммиты не запускают CI; отдельные функции не выпускаются отдельными релизами.

Незавершённые сквозные проверки VPN-мастера, перенос изменяемых данных AmneziaWG и следующие направления перечислены в [ROADMAP.md](ROADMAP.md). Этот документ фиксирует состояние подготовки и границы выпуска, а не объявляет все направления завершёнными.
