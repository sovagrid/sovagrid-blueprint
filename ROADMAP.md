# План развития SovaGrid

SovaGrid состоит из независимых установок: каждый Ubuntu-сервер может хранить собственные Hub, Agent, учётные записи и данные. SSH-подключение не требует общего сервиса аккаунтов. Публичные инструкции используют общие примеры и одноразовые тестовые среды.

Текущий согласованный выпуск — [server-v1.0.0](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v1.0.0). Состав серверной и клиентской поставки, проверки и поддерживаемые границы собраны в [RELEASE_1_0.md](RELEASE_1_0.md).

## Возможности 1.0

- **Подключение и первая установка.** Apple, Android и Connect подключаются по SSH с паролем или ключом, проверяют ключ сервера и поддерживают один промежуточный SSH-хост с отдельными учётными данными и проверкой ключа. Все клиенты, включая Web, умеют создавать пару Ed25519 и показывать публичный ключ для переноса на сервер. Приложение может подготовить пустой Ubuntu по SSH; [однокомандная установка](QUICKSTART.md) объясняет выбор публичного IPv4 или домена и пути панели. Установка, обновление и восстановление используют общую раннюю блокировку.
- **Web и приложения.** Web/PWA предоставляет вход через SSH на хост панели и локальный вход Hub, терминал, команды, файлы, мониторинг и настройки. Администратор настраивает путь панели и поведение корня сайта. Есть светлая, тёмная и системная темы, а также установка ярлыка PWA. Apple и Android используют системный выбор и сохранение файлов; отдельный механизм восстановления читает крупные архивы порциями. Обычная загрузка файлов во встроенной панели сохраняет ограничение 4 МиБ.
- **Доступ и управление Ubuntu.** Hub хранит локальные аккаунты, роли, права на конкретные серверы и аудит. Agent передаёт метрики CPU, памяти, дисков, inode, сети, процессов, служб и контейнеров. Команды, терминал, файловые корни, выбранные журналы systemd и действия со службами включаются отдельными политиками. Telegram-токен вводится в панели; бот проверяет права и подтверждение команды.
- **Мониторинг.** Поддерживаются HTTP/HTTPS, TCP и DNS-проверки, пороги, окна обслуживания, инциденты и очередь уведомлений. Временные значения хранятся в UTC, интерфейс показывает время устройства. Отдельные правила для сертификатов, inode и выбранных томов включаются явно.
- **Дополнительные серверы.** Connect и веб-мастер готовят Agent по прямому SSH-маршруту или через промежуточный хост: проверка ключей, план, отдельное подтверждение запуска, сохранённый ID операции, повторное подключение и очистка. До установки Agent глобальный администратор может открыть прямой SSH-терминал из Web. Пароли и приватные SSH-ключи веб-мастера не сохраняются в его журналах.
- **VPN.** Поддерживаются собственный WireGuard, управление поддерживаемыми установками AmneziaWG, клиенты и защищённое скачивание профиля. Есть автоматический выбор свободного IPv4 клиента. Для AWG3 изменение числовых параметров требует отдельного подтверждения и поддерживаемого состояния без клиентов. Agent передаёт ограниченную VPN-сводку, привязанную к правам на сервер. В Web реализованы подготовка VPN-кода, установка брокера, подключение существующего брокера и отдельное включение управления, включая маршрут через промежуточный SSH-хост. Обслуживание исходников при установленном брокере имеет отдельную транзакцию и восстановление после обрыва. Полная сквозная проверка всех VPN-шагов Web фиксируется отдельно; наличие этих шагов в исходниках не означает уже подтверждённый результат.
- **Обновление.** Сервер использует подписанную ленту с явным включением подписки, проверку архива и манифеста, ожидание простоя, откат и восстановление незавершённых операций. Поддерживаемая Hub-only установка имеет отдельный путь обновления, сохраняющий внешний Agent и SSH-транспорты. Обновление внешнего Agent согласует остановку с исходным Hub, проверяет пробный запуск и использует watchdog.
- **Резервные копии и перенос.** Администратор создаёт и проверяет связанную копию из пяти файлов: архив хоста, его манифест, Docker-образы, их манифест и квитанция. В Web и Connect реализованы мастер переноса, проверенный независимый исполнитель, подготовка зависимостей, порционная передача, план, сохранённая операция и повторное подключение. Backend реализует транзакцию применения, карантин очереди, проверку здоровья, откат, восстановление и явную новую попытку после полного отката. Возможность запуска определяет capability независимо проверенного исполнителя; текущий статус включения и Ubuntu-проверки собран в [RELEASE_1_0.md](RELEASE_1_0.md).

## Подтверждённые проверки 1.0

- [Обновление опубликованной 0.14.1 по подписанной ленте](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41298983265) прошло настоящими установленными модулями старой версии: отказ при повреждённой подписи, ожидание занятого сервера, применение в простое и последующий откат намеренно ошибочного кандидата. В тесте используется одноразовый ключ подписи.
- [Hub-only миграция 0.14.1 и следующее подписанное обновление](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41298989964) прошли с проверкой отката и сохранности внешнего Agent и SSH-транспортов. Для Hub-only 0.14.1 сначала нужен разовый ручной переход; подписка нового пути включается после него.
- [Общий интеграционный прогон](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41332122229) подтвердил зависимости, повторный bootstrap, обслуживание VPN-кода, полную установку, работающие Hub/Web/Agent, watchdog, дополнительные Ubuntu через Connect и Web, подписанное обновление и три сценария переносимого восстановления: аварийный откат, настоящее применение с первым переподключением во время работы и сохранение изменившейся SQLite при ошибке здоровья.
- Последние полные локальные наборы прошли: Blueprint 949 тестов (21 пропущен по окружению), Connect 518 (32 пропущено), Web 388 и gateway 79. Мастера восстановления и прав Agent проверены в браузере на ширине компьютера и телефона.
- Реальная цепочка Core → Web-журнал → gateway проверила строгую политику full/v2 и сохранение review SHA. Семь настоящих экспортов Docker 28.5.2/29.5.2 подтвердили legacy/OCI/classic hybrid форматы и привязку config/RootFS/platform.
- Web-мастер прав Agent прошёл настоящий HTTP/SSH-маршрут через промежуточный хост, план и подтверждение, включая закрытую политику до окончания очистки. Полная цепочка WireGuard из Web создала защищённый профиль, которым отдельный kernel-клиент выполнил handshake и двусторонний обмен пакетами. Автоматическая установка AmneziaWG на ARM64 явно отказывает; новая полная проверка этого Web-сценария на amd64 пока не заявляется.
- iPhone Simulator и Android API 30/36 проверили системный выбор, сохранение и передачу файлов встроенной панели. Отдельный выбор архива восстановления проверен на настоящем файле размером более 8 МиБ с чтением порциями и проверкой хешей. Клиенты Apple 1.0.0/build 16 и Android 1.0.0/code 17 закрепляют согласованный серверный архив 1.0.0. Это не проверка установки на физический iPhone.
- Ранее [сквозное обновление внешнего Agent](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41207706488) и [IPv4-маршрут AmneziaWG](https://github.com/sovagrid/sovagrid-vpn/actions/runs/41190306888), включая профиль, handshake, NAT и HTTP, прошли отдельные одноразовые проверки. Они не заменяют будущую сквозную проверку VPN-мастера Web.

## Границы переносимого восстановления

Текущая реализация принимает полный layout с квитанцией v2 и чистую Ubuntu-цель с systemd, root SSH или уже настроенным sudo без запроса пароля. Старые квитанции v1 можно проверить и подготовить, но применить нельзя. Hub-only, активное состояние VPN-маршрутизации, неподдерживаемые файловые корни и изменение публичного адреса блокируют план до подтверждения. Ожидающие команды и подтверждения Telegram из копии отменяются до запуска служб; поддерживаемая VPN-конфигурация переносится с выключенными интерфейсами. План также учитывает дополнительный запас 8 ГиБ для проверки образов при смене storage format; Compose использует проверенный immutable ID. Подробности: [контракт копии и транзакции](HOST_BACKUP.md), [Web-мастер](deploy/WEB_PORTABLE_RESTORE.md) и [протокол цели](deploy/PORTABLE_RESTORE_TARGET.md).

**Переносимое восстановление AmneziaWG пока не поддерживается.** Архив хоста сохраняет журналы установки, но не актуальную изменяемую конфигурацию и таблицу клиентов внутри Docker-контейнера. Экспорт образов также не включает отдельный AWG-образ. План отказывает с `VPN_PORT_UNVERIFIED`; успешного переноса с потерей этих клиентов не происходит. Для поддержки нужны согласованный снимок VPN-данных, образ и отдельное восстановление контейнера с проверкой и откатом.

## Поставка 1.0

Серверный архив и его манифест закреплены в bootstrap основной ветки, Connect, Apple и Android; точные хеши опубликованы с [выпуском](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v1.0.0). [Подписка на серверные обновления](RELEASE_FEED.md) включается отдельно на каждом поддерживаемом Hub.

Connect распространяется сборками для компьютеров, Android — APK с прежним ключом подписи, Apple — исходным проектом и сборкой macOS. Для своего iPhone используется Xcode и личный Apple ID; App Store и Google Play не требуются. Проверка на физических телефонах остаётся отдельным этапом.

## Следующие серверные возможности и сопровождение

- Завершить сквозную проверку подготовки VPN-кода, установки брокера и создания AmneziaWG из Web на отдельном Ubuntu, напрямую и через промежуточный SSH-хост; проверить подключение физического телефона, внешний Интернет и IPv6.
- Добавить согласованный снимок изменяемого состояния управляемого AmneziaWG и перенос его контейнера, образа и клиентов. До этого сохранять явный отказ переносимого восстановления такой установки.
- Для старого внешнего Agent без idle-сокета добавить отдельный однократный bootstrap; расширить интерфейс разбора операций с неопределённым исходом. Старые 0.13.0/0.14.0 требуют разовой ручной миграции через Connect.
- Подготовить внешнюю резервную копию ключа подписи выпусков и регламент продления ленты: текущий формат ограничивает срок подписанного документа 30 днями. Это задача сопровождения публикации, а не настройка на каждом клиентском сервере.

- Добавить отдельный перенос управляемых Hub-side SSH-транспортов внешних Agent с проверкой ключей и нового адреса. Текущий архив сохраняет записи серверов в Hub, а сами SSH-транспорты после переноса нужно настроить заново; системные SSH host keys Ubuntu не копируются.

## Дальнейшие направления

- Детальный мониторинг хранилищ и баз данных, Kubernetes-инвентарь и разрешённые действия над выбранными ресурсами.
- Временный доступ, OIDC/passkeys, дополнительные политики команд и расширенный аудит.
- Отдельные нативные клиенты Windows и Linux; до них настольный доступ предоставляет Connect.
- Внешний наблюдатель на другом хосте: Hub на отключившемся сервере не может отправить собственную тревогу.
- Провайдеры и плагины для дополнительных панелей, расширенные API и CLI. Новый экспериментальный VPN-протокол относится к отдельному исследованию после завершения основного продукта и анализа безопасности.
