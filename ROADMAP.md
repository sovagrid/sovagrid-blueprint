# План развития SovaGrid

SovaGrid строится как набор независимых установок: каждый Ubuntu-сервер может хранить собственные Hub, Agent, учётные записи и данные. Подключение через SSH не требует общего сервиса аккаунтов. Публичная документация описывает воспроизводимые сценарии и одноразовые тестовые среды; адреса и состояние частных установок в ней не публикуются.

Функции собираются пакетами: сначала согласуются контракты Hub, Agent, VPN и обновлятора, затем интерфейсы Web, Connect, iOS и Android. Коммит в исходниках не означает, что функция доступна в ранее выпущенных приложениях. Перед серверным выпуском пакет проходит проверку манифеста, чистую установку на одноразовой Ubuntu и тест отката. Мобильные приложения выпускаются отдельным общим этапом.

## Реализовано в исходниках

- SSH-вход по ключу и паролю, проверка ключа хоста, терминал, SFTP и подключение через промежуточный SSH-хост. Apple, Android, Connect и Web умеют создавать пару Ed25519; интерфейс показывает публичный ключ для переноса на сервер, а Web выдаёт приватный ключ отдельным скачиванием.
- Hub с локальными учётными записями и ролями, отдельными правами на серверы, одноразовым входом после root/sudo SSH и Telegram-ботом с подтверждением команд. Токен BotFather вводится в панели.
- Agent для Ubuntu: метрики CPU, памяти, файловых систем, сети, процессов, служб и контейнеров. Доступ к командам, терминалу, файлам, выбранным журналам systemd и действиям со службами включается отдельно; root-брокеры проверяют точные разрешения.
- Мониторинг HTTP/HTTPS, TCP и DNS, пороги, окна обслуживания, инциденты и очередь уведомлений. Настройки и метки времени хранятся в UTC; интерфейс показывает локальное время устройства. Отдельные правила по TLS-сертификатам, inode и выбранным томам по умолчанию выключены.
- Web/PWA с SSH-входом на хост панели, собственным входом Hub, терминалом, файлами, мониторингом, светлой и тёмной темами и установкой ярлыка на телефон. Путь панели и поведение корня настраиваются администратором. В разделе добавления сервера глобальный администратор может открыть прямой SSH-терминал до установки Agent: пароль или ключ, сверка ключа хоста и один проверенный промежуточный SSH-хост. Двоичные файлы скачиваются до 32 МБ, загрузка ограничена 4 МБ.
- Веб-мастер для следующего Ubuntu-сервера: отдельная проверка SSH-ключа, вход root по паролю или приватному ключу, просмотр состояния и сетевого пути, подготовка Agent, отдельное подтверждение запуска, восстановление и очистка. Hub хранит закрытый журнал, проверенный пакет и историю завершённых установок; прямое обновление и резервная копия согласованы с незавершённой операцией. Подготовка и очистка проверены на отдельном временном Ubuntu-узле.
- Веб-мастер для AmneziaWG 2 и WireGuard на хосте панели и другом Ubuntu-сервере с прямым SSH-доступом из Hub: проверка ключа и существующего контейнера, подключение по четырём отпечаткам состояния, установка брокера и отдельное включение управления с подтверждением окна обслуживания. Для удалённого хоста добавлена отдельная подготовка VPN-кода из проверенного пакета с предпросмотром, сверкой ревизии и восстановлением после обрыва. Каждый шаг повторно проверяет права администратора, адрес и состояние; браузер не сохраняет SSH-данные. Подготовка кода не создаёт VPN-контейнер и не включает брокер.
- Agent передаёт Hub ограниченную VPN-сводку каждого Ubuntu-сервера; Hub хранит только очищенные поля и отдаёт их пользователям с доступом к этому серверу. Web показывает выбранный сервер и отдельно хост панели, помечает устаревшие данные и отсутствие поддержки у старого Hub. Серверный SSH-мост установки обычного WireGuard-брокера на другом хосте поддерживает предпросмотр, сверку ревизий и восстановление; установка не включает VPN-интерфейс. Веб-шаг прошёл локальные контрактные проверки; живой запуск на чистом удалённом Ubuntu ещё предстоит.
- Веб-вкладка VPN проверяет маршрут к Ubuntu через один промежуточный SSH-хост: отдельно подтверждает оба ключа, проверяет вход и читает фиксированное состояние. Установка и управление VPN через этот маршрут пока не доступны.
- Собственный WireGuard с ограниченным root-брокером и защищённой выдачей профиля автоматически назначает клиенту свободный IPv4-адрес. Для управляемого AmneziaWG панель предлагает автоматический выбор первого свободного адреса или ручной адрес; Amnezia наблюдается отдельно; управление AWG2/WireGuard и числовыми параметрами AWG3 является opt-in. Для AWG3 применение плана возможно только на проверенной установке без клиентов и после отдельного подтверждения.
- [Проверенный server-v0.12.0](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v0.12.0) из пяти репозиториев, графическая установка и ручное обновление через Connect с резервной копией и откатом. Одноразовый серверный таймер применяет только заранее выбранный администратором архив и отказывается от изменения при занятом Agent или Hub.
- Закрытые резервные копии Hub и управляемого состояния хоста с проверкой плана и восстановлением после обрыва. Архивы с секретами не выдаются через Web API.
- Отдельное подтверждаемое обновление внешнего Agent на сервере с собственным Hub: root lease исходного Hub, idle ACK исходного Agent, точная остановка, пробный запуск с watchdog, откат и восстановление после обрыва. Hub запускает операцию через фиксированную systemd-службу; Web показывает план, подтверждение, UUID и сохранённое состояние. [Сквозной тест на одноразовой Ubuntu](https://github.com/sovagrid/sovagrid-blueprint/actions/runs/41207706488) прошёл.

## Следующий серверный этап

- Для старого внешнего Agent без idle-сокета разработать отдельный однократный bootstrap. Добавить в панель разбор операций обновления с неопределённым исходом: они сейчас блокируют дальнейшую замену Hub до ручной проверки состояния.
- Завершить сквозную проверку запуска Agent из веб-мастера на чистом временном Ubuntu-хосте, включая восстановление после обрыва и удаление тестового узла. Первый Hub устанавливается через Connect, мобильный SSH-клиент или `run.sh`: пустой сервер ещё не может предоставлять собственную веб-панель и SSH-шлюз.
- Проверить подготовку VPN-кода и подключение Amnezia из Web на чистом удалённом Ubuntu-хосте. Добавить безопасное обновление VPN-кода при уже установленном брокере и защищённую установку через промежуточный SSH-хост; оба ключа пока проверяются только в режиме чтения. Прямое SSH-подключение для установки уже поддерживается.
- Полный IPv4-маршрут AmneziaWG, запечатанный профиль, handshake, NAT и HTTP через AWG прошли [одноразовый ручной тест Ubuntu 24.04](https://github.com/sovagrid/sovagrid-vpn/actions/runs/41190306888). Остались живой запуск из Web-мастера на отдельном Ubuntu, подключение настоящего телефона, внешний Интернет и IPv6. Маршрут только к выбранной подсети проверялся отдельно локально.
- Завершить стабильный подписанный канал обновлений: публичный Ed25519 ключ уже закреплён, приватный хранится вне Git/CI/серверов; остаются независимая сверка отпечатка, резервное хранение ключа, стабильный пакет, публикация подписанной ленты и сквозной тест получения и отката. Preview-пакет не включается в стабильную ленту автоматически.
- Проверить первую установку server-v0.12.0 с физических iOS и Android устройств на отдельном Ubuntu-хосте; закреплённые URL и хеши клиентов обновлять синхронно с серверным пакетом.
- Проверить восстановление управляемого состояния на другом чистом Ubuntu-хосте, перенос Docker-образов и завершённое восстановление после частичной ошибки.
- Для созданного SovaGrid контейнера AmneziaWG добавить резервное копирование изменяемой конфигурации и таблицы клиентов из Docker, а также безопасное восстановление контейнера и образа на другом хосте. Текущий полный архив хоста включает журнал установки в `/var/lib/sovagrid-vpn`, но не изменяемый слой Docker после добавления клиентов.

## Дальше

- Детальный мониторинг хранилищ и баз данных, Kubernetes-инвентарь и разрешённые действия по явно выбранным ресурсам.
- Политики команд по действиям, временный доступ, OIDC/passkeys и расширенный аудит без секретов.
- Нативные клиенты Windows и Linux, общая проверка на физических телефонах и единый мобильный релиз после серверной стабилизации.
- Внешний наблюдатель на отдельном хосте для обнаружения полного отключения сервера: Hub на отключившемся сервере не может отправить собственную тревогу.
- Провайдеры и плагины для дополнительных панелей, расширенные API и CLI. Экспериментальный новый VPN-протокол относится к отдельному исследованию после завершения основного продукта и анализа безопасности.
