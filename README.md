# SovaGrid

SovaGrid — набор отдельных приложений и служб для доступа к Ubuntu-серверам, наблюдения за их состоянием и реагирования на события.

## Репозитории

| Репозиторий | Назначение |
|---|---|
| [sovagrid-hub](https://github.com/sovagrid/sovagrid-hub) | API, пользователи, роли, история метрик, инциденты, Telegram и очередь заданий |
| [sovagrid-agent](https://github.com/sovagrid/sovagrid-agent) | Сбор метрик и исполнение явно разрешённых заданий на Ubuntu |
| [sovagrid-apple](https://github.com/sovagrid/sovagrid-apple) | Нативные приложения для iPhone, iPad и macOS |
| [sovagrid-android](https://github.com/sovagrid/sovagrid-android) | Нативное приложение для Android |
| [sovagrid-web](https://github.com/sovagrid/sovagrid-web) | Веб-панель для компьютера и мобильного браузера |
| [sovagrid-connect](https://github.com/sovagrid/sovagrid-connect) | Настольный запуск полной веб-панели через SSH для macOS, Linux и Windows, включая ProxyJump |
| [sovagrid-vpn](https://github.com/sovagrid/sovagrid-vpn) | Раздельный сбор состояния Amnezia и собственного WireGuard без доступа Hub к Docker socket; root-only CLI для WireGuard |
| [sovagrid-blueprint](https://github.com/sovagrid/sovagrid-blueprint) | Установщик, архитектура, модель доступа и план развития |
| [sovagrid-update-feed](https://github.com/sovagrid/sovagrid-update-feed) | Отдельное хранилище будущих подписанных метаданных серверных релизов; канал пока выключен |

Девять репозиториев находятся в [организации sovagrid](https://github.com/sovagrid). Исходники открыты по AGPLv3 с сохранением авторства Jigokuraku01.

Серверные исходники собираются в пакет с точным манифестом. Перед установкой проверьте совместимость пяти компонентов и происхождение пакета. [Проверенный серверный prerelease server-v0.12.0](https://github.com/sovagrid/sovagrid-blueprint/releases/tag/server-v0.12.0) доступен для собственной установки. [Быстрый запуск](QUICKSTART.md) и [подробная инструкция](DEPLOY.md) рассчитаны на ваш собственный Ubuntu-сервер. Подписанная лента будущих стабильных версий пока не активирована.

Пять серверных репозиториев можно собрать в [переносимый пакет](package_server.py) без локальных секретов и Git-метаданных. На новом Ubuntu-сервере [SovaGrid Connect](https://github.com/sovagrid/sovagrid-connect) принимает этот пакет через графическое окно, проверяет его, передаёт по SSH и запускает установку. На уже установленном сервере Connect может включить WireGuard, терминал, файловый раздел и чтение журналов выбранных systemd-служб через отдельное подтверждённое действие после проверки исходников и служб. Для журналов устанавливается отдельный непривилегированный broker с собственным перечнем точных имён `.service`; пользователь Agent не входит в группу `systemd-journal`. Доступ к приватному GitHub и ввод токена на сервере не требуются. SSH-пароли, первый пароль Hub, пороги мониторинга и токен BotFather вводятся или копируются в интерфейсе. Создание пакета из исходников остаётся задачей сборки; готовый пакет можно передать пользователю вместе с приложением.

Для резервной копии всего управляемого состояния хоста есть [root-only backend и контракт Connect](HOST_BACKUP.md). Он архивирует секреты отдельно от снимков базы Hub. Подтверждённый запрос через Connect ведётся независимым systemd worker: он временно останавливает только локальные writer-службы, создаёт копию с заранее закреплённым ID и восстанавливает исходные состояния даже после обрыва SSH.

## Первые сценарии

1. Пользователь добавляет SSH-профиль и выполняет команды в мобильном приложении. Профиль поддерживает вход по паролю или ключу, а ключ хоста проверяется до отправки учётных данных. Для сервера за промежуточным SSH-хостом можно указать отдельные учётные данные и ключи обоих узлов.
2. Администратор создаёт сервер в Hub. Hub показывает токен агента один раз; агент на Ubuntu отправляет метрики по исходящему HTTPS-соединению.
3. С телефона пользователь открывает веб-панель через временный SSH-проброс к выбранному серверу с Hub; при необходимости маршрут проходит через промежуточный SSH-хост. На компьютере то же делает SovaGrid Connect. Начальный пароль можно скопировать в этих приложениях после SSH-входа без чтения файла в консоли. Панель показывает метрики, историю, последние десять процессов по памяти, инциденты, окна обслуживания, журнал, очередь команд, подробное состояние Amnezia и собственные WireGuard-инстансы SovaGrid. Системная, светлая и тёмная темы выбираются на каждом устройстве отдельно. Процессы передаются без аргументов команд и не записываются в историческую базу. В «Настройках» администратор меняет пароль и пороги тревог без перезапуска. Ошибка одного источника не скрывает состояние другого.
4. Администратор может запустить разовую команду или несколько независимых вкладок интерактивного терминала из панели при включённой функции на сервере и в Agent. Терминал работает от пользователя `sovagrid-shell` без доступа к токену Agent; его байты не попадают в аудит. Файловый раздел позволяет читать и править небольшие текстовые файлы, загружать двоичные файлы до 4 МБ и скачивать до 32 МБ только в разрешённых на Agent каталогах. Журналы systemd читаются только для явно разрешённых служб после отдельного включения; их просмотр требует разрешённых удалённых команд в Hub и Agent. В разделе Telegram администратор вставляет токен BotFather, а пользователь отправляет боту `/start`; заявка появляется в панели, где администратор подтверждает роль `viewer`, `operator` или `admin`. Привязанные пользователи могут запросить сводку VPN через `/vpn`; Telegram-команда на сервере дополнительно требует роль `admin` и подтверждение.
5. При необходимости администратор отдельно включает стандартный WireGuard: `run.sh --with-wireguard` готовит зависимости и локальный root broker. В панели администратор выбирает сервер с Agent и после подтверждения может подготовить инстанс, запустить его, добавить или отозвать клиента, скачать клиентский профиль `.conf` или удалить инстанс. При скачивании браузер создаёт временную пару ключей; брокер шифрует профиль до передачи Agent и Hub. Нативные приложения предлагают системное сохранение после расшифровки в веб-панели. Закрытый ключ профиля не попадает в базу Hub. Выбранный Agent отправляет собственную очищенную VPN-сводку примерно раз в 30 секунд; панель показывает её свежесть отдельно от состояния VPN на хосте Hub. Панель содержит также отдельное управление профилями AmneziaWG: оно доступно только после ручного закрепления контейнера и включения отдельного брокера на целевом хосте; обычный `run.sh` существующую Amnezia не меняет.

В установленной веб-панели администратор может открыть «Добавить сервер → Подключить по SSH → Открыть SSH-терминал» ещё до установки Agent на целевой Ubuntu: указать пароль, приватный или созданный в браузере ключ, сверить отпечаток SSH-хоста и при необходимости пройти через один проверенный промежуточный хост. Сеанс интерактивный и ограничен по времени; для самой веб-панели сначала нужен свой установленный Hub. Обновление исходного внешнего Agent на сервере с собственным Hub доступно отдельно в «Настройки → Обновление внешнего Agent» после подготовки пакета через Connect и просмотра точного плана.

Текущая реализация и ограничения каждого приложения описаны в README соответствующего репозитория. План дальнейшей разработки: [ROADMAP.md](ROADMAP.md).

Быстрый запуск на Ubuntu: [QUICKSTART.md](QUICKSTART.md). Полная инструкция по [run.sh](run.sh), секретам и проверкам: [DEPLOY.md](DEPLOY.md).

## Удалённый Agent

Новый Agent-only protocol для Connect описан в [REMOTE_AGENT.md](REMOTE_AGENT.md): постоянное подключение другого Ubuntu через существующий SSH endpoint Hub, подготовка token и ключа на target, безопасный повтор и ограниченный отзыв доступа. После установки Hub тот же сценарий доступен в веб-панели через мастер «Добавить сервер → Подключить по SSH»: он сверяет ключ целевого сервера, проверяет состояние, показывает подготовленную установку и требует отдельного подтверждения запуска. [Требования и порядок](DEPLOY.md#добавление-другого-ubuntu-сервера-из-веб-панели) описаны в инструкции. Для этого сценария Hub сначала обновляется обычным способом до версии с enrollment API и проверенным helper; старый установленный Hub не изменяется по неподтверждённому сценарию.

Журнал root helper ограничен 4 МиБ на узел. На Hub сохраняются до 2048 enrollment-записей, включая отозванные, и до 256 неотозванных разрешений туннеля, включая незавершённые установки. При достижении лимита новая авторизация отказывается без изменения ресурсов; проверка, отзыв и точный повтор существующей авторизации остаются доступны. JSON-запросы и ответы helper по-прежнему ограничены 32 КиБ.
