# Безопасность и роли

| Роль | Метрики и инциденты | Подтверждение инцидента | Настройка серверов и пользователей | Произвольные команды |
|---|---:|---:|---:|---:|
| `viewer` | ✓ | — | — | — |
| `operator` | ✓ | ✓ | — | — |
| `admin` | ✓ | ✓ | ✓ | ✓, после подтверждения |

Правила применяются в Hub, а не только в интерфейсе. Telegram `username` не служит идентификатором: он меняется; проверяется числовой `user_id` вместе с привязанным личным `chat_id`. Групповые чаты не должны принимать команды исполнения.

Команды через Telegram несут высокий риск. Для них требуются явное включение в Hub и локально на агенте, короткий срок подтверждения, ограничение времени, ограничение вывода, отдельный системный пользователь без `sudo`, журнал с автором, сервером, временем, кодом завершения и результатом. Текст команды может содержать секреты; в аудит следует сохранять его с доступом только администратора и с установленным сроком хранения. Нельзя добавлять Telegram-бота в привилегированную группу или запускать агента от root.

Администратор должен самостоятельно проверить первый SSH fingerprint по доверенному каналу. При смене host key приложение останавливает подключение до явного разбора причины. Использование `accept all` запрещено.

Hub по умолчанию слушает только loopback. Доступ извне открывается через HTTPS reverse proxy с актуальным сертификатом и ограничением размера запросов. Токен Telegram хранится вне репозитория с доступом только к учётной записи службы. Резервная копия базы данных должна шифроваться и регулярно проверяться восстановлением.

Перед публикацией или эксплуатацией нужны независимый просмотр кода, проверка зависимостей, тесты на реальные iOS/Android-устройства и проверка ролевых сценариев. Текущий статус конкретных проверок отражён в README приложений.
