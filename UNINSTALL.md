# Удаление SovaGrid

Запустите обычный `run.sh` на сервере. Чтобы проверить состав установки и вывести план, выполните:

```bash
bash -o pipefail -c 'curl -fsSL https://github.com/sovagrid/sovagrid-blueprint/releases/latest/download/run.sh | sudo bash -s -- --uninstall --plan'
```

Для удаления запустите ту же команду с `--uninstall` и введите `REMOVE SOVAGRID` после проверки плана.

## Hub и подключённые Agent

При удалении Hub мастер перечисляет Agent, которые были установлены через этот Hub. Для каждого потребуется профиль из `~/.ssh/config` с проверенными ключами узлов. Можно использовать `ProxyJump` с несколькими переходами. Конечному SSH-пользователю нужны права root или доступ через `sudo -n`. При запуске команды через `sudo` используются SSH-профили запустившего её пользователя.

Готовые профили можно передать параметрами `--route SERVER_ID=SSH_PROFILE`. Hub удаляется после подтверждения удаления от всех управляемых Agent. При обрыве связи Hub остаётся доступен для повторной попытки. Уже удалённый Agent подтверждает результат по локальной квитанции. Незавершённую установку Agent сначала нужно завершить или отменить в панели.

В режиме Hub-only удаляется локальный Hub и связанный с ним локальный Agent. Исходный Agent, подключённый к другому Hub, сохраняет своё подключение, службы и файлы.

## Прямое удаление Agent

На сервере, где установлен только управляемый Agent, используйте `--uninstall --agent-only`. Эта команда удаляет службы Agent и полномочия терминала и файлового доступа. Запись сервера и история метрик остаются в его Hub. Чтобы удалить Hub вместе со всеми управляемыми Agent, запустите удаление на Hub.

Рабочие файлы Agent и домашний каталог выделенного пользователя терминала сохраняются. Путь переноса резервных копий Hub выводится при удалении. Рабочие файлы удалённого Agent с терминалом или файловым доступом хранятся под `/var/lib/sovagrid-agent-enrollment/retained-<enrollment-id>/` на самом Agent. Доступ к сохранённым файлам есть у root.

Скрипт проверяет принадлежность установленных служб, настроек и регистраций. Независимые службы SSH, чужие контейнеры и существующая конфигурация WireGuard сохраняются. Если происхождение Agent или его ресурсов подтвердить не удаётся, скрипт выводит причину и оставляет Hub доступным.
