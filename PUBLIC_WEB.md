# Public Web HTTPS

Public access is an explicit option for an existing managed SovaGrid installation. The default installer continues to publish only `127.0.0.1:8766` and `127.0.0.1:8767`. Public access adds TCP 80 and 443 to the existing Web container. It does not publish Hub port 8765 or the Agent ingress on 8767, alter VPN services, or create a second proxy.

Web uses Caddy 2.11.7 pinned by the official multi-platform Docker manifest digest. For an IP address, the explicit Let's Encrypt ACME issuer selects the `shortlived` profile. Caddy obtains and renews the certificate automatically using the existing persistent `/var/lib/sovagrid/caddy` storage. No renewal cron, extra Docker socket, certificate copying, user token, or DNS-provider credential is required. IP certificates last 160 hours. [Let's Encrypt availability](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability), [Caddy ACME settings](https://caddyserver.com/docs/caddyfile/directives/tls).

TCP 80 and 443 must already be reachable from the Internet. The helper refuses an unrelated service using either port; it does not rewrite firewalls, configure a hosting provider, stop other containers, or rewrite DNS. DNS mode requires a lowercase public hostname whose resolved addresses belong to this server. An IP address must be canonical and globally routed. A later DNS or routing change can prevent renewal and must be corrected by the operator.

The first public stack supports IPv4 and DNS A records only, with explicit `0.0.0.0` host bindings. Any proposed IPv6 address or resolved AAAA address receives `IPV6_UNAVAILABLE`. The existing private Docker bridge is IPv4-only; accepting IPv6 through Docker's userland proxy could collapse distinct clients to one gateway address. Dual-stack public deployment needs a separately verified Docker networking increment. HTTP/1.1 and HTTP/2 are enabled; HTTP/3 is disabled because the high internal port would need separate UDP publication and address handling.

The public site redirects HTTP to its fixed HTTPS address, rejects unknown Host values, and forwards the actual socket client IP to Hub through the existing trusted Web address. Client-supplied `X-SovaGrid-Client-IP` values are overwritten. Agent metric uploads, command polling/results, file relay, terminal relay and availability-check worker routes are denied on the public site; browser login, monitoring, commands, terminal, files, VPN, roles and settings continue to use the authenticated panel API. Agent traffic continues through the separate SSH channel.

The existing Web PWA can be installed from the browser once its public origin has a trusted certificate. A staging certificate is explicitly a diagnostic certificate and is never reported as trusted. API responses, authentication and exported profiles are not eligible for service-worker caching.

The panel opens at `/sovagrid/monitoring/` by default. An administrator can choose another panel path and the behavior of `/` in Connect or the Web admin settings. New configurations select `untouched`: the dedicated SovaGrid public host returns 404 at `/` and unknown paths instead of Caddy's empty 200, while the local SSH-only listener keeps its existing root page. Previously saved configurations retain their `panel` behavior until the administrator changes it. `redirect` sends `/` to the selected panel path with HTTP 308; `not_found` explicitly returns 404 at `/`. The original `/sovagrid/monitoring/` remains a working alias when the selected path changes. The PWA manifest launches from this stable alias even when loaded from a custom panel path. On iPhone or iPad, the install panel links to the stable alias so manual Add to Home Screen starts there. Its service worker controls only the alias; manifest scope `/` keeps both panel routes in the app window but does not alter HTTP routing at `/`. Shortcuts installed before this change on a custom route may need to be added again if that route has already been removed; changing the IP or domain also requires a new shortcut. The panel path is a route, not an access control or a secret. The public HTTPS and local `127.0.0.1:8766` listeners use the configured path while public Web is enabled; without that configuration the local listener uses the default path and keeps its existing root page. `/api/v1/*` and `/healthz` stay at their fixed root-level paths.

## Internal SSH helper protocol

`/opt/sovagrid-src/sovagrid-blueprint/deploy/public_web.py` is an internal root helper for the Connect configuration dialog. The client must verify the installed source manifest and helper bytes **before executing** it. The helper then verifies root ownership, file hashes, the managed install marker and public configuration itself. The manifest establishes the integrity of the operator-approved installed bundle, not independent publisher authenticity.

The single command argument selects `status`, `preview`, `apply` or `disable`. Requests use UTF-8 JSON on stdin, at most 4096 bytes, no duplicate keys or non-finite numbers, and depth at most 32. No password, token or private key is accepted. Errors use a fixed code; clients must not display arbitrary remote text.

`Config` accepts these fields; `panel_path` and `root_behavior` are optional for older clients and stored configurations:

```json
{"mode":"ip","address":"YOUR_PUBLIC_IPV4","acme_environment":"production","panel_path":"/sovagrid/monitoring/","root_behavior":"panel"}
```

`mode` is `ip` or `dns`; `acme_environment` is `production` or `staging`. DNS labels are ASCII, lowercase, 1–63 characters without leading/trailing hyphens; the full hostname is at most 253 characters, with at least two labels and an alphabetic first TLD character. Wildcards, URL components, ports, local/test names and arbitrary Caddy configuration are rejected.

`panel_path` must start and end with `/`, contain 1–3 lowercase ASCII segments using letters, digits or internal hyphens, and be at most 96 characters. Paths beginning with `/api/` or `/healthz/` are reserved. `root_behavior` is `untouched`, `panel`, `redirect` or `not_found`. Omitted values normalize to `/sovagrid/monitoring/` and `panel` only for migration of saved pre-migration configurations; new UI requests explicitly send `untouched`. A path or root change creates a new hashed generation under compare-and-swap; failure to serve the selected panel path, service worker or root behavior restores the prior generation. If the managed SSH gateway is present, the public SSH host-key route is verified before success. Older deployments with a deferred gateway can still publish HTTPS, but SSH login becomes available only after the gateway update.

| Operation | Request | Successful response |
| --- | --- | --- |
| `status` | No request body | `protocol:1, ok:true, enabled, config:Config|null, expected_state_sha256:SHA256|null` |
| `preview` | `{config:Config}` | `protocol:1, ok:true, config, expected_state_sha256, source_manifest_sha256, changed, url, certificate_verified:false` |
| `apply` | `{config:Config, expected_state_sha256:SHA256|null, source_manifest_sha256:SHA256}` | Preview fields plus `enabled:true`; state hash identifies the committed generation; `certificate_verified:true` only after strict production TLS/health verification |
| `disable` | `{expected_state_sha256:SHA256|null}` | `protocol:1, ok:true, enabled:false, changed, expected_state_sha256:null` |

Read-only preview does not create a directory, acquire a write lock, contact ACME or issue a certificate. It verifies current source/state, local HTTP and Agent TLS health, port availability and the proposed IP/DNS relationship. DNS and public TLS checks execute in independently bounded child processes, so a blocked system resolver cannot hold the GUI indefinitely.

Apply repeats preview under the shared operation lock and compares both source and state hashes. Immutable, hashed configuration generations live below root-private `/etc/sovagrid/public-web`. The selected state is published atomically before changing Web so an interrupted operation can converge when explicitly retried. An exact retry verifies that the running container mounts the committed generation; an older still-answering site cannot falsely prove success. Only Web is recreated. The validator uses a separate network-less, unprivileged, read-only container with temporary CA storage, avoiding the live Web static IP and certificate storage. Failed apply restores the prior configuration and verifies the prior channels. A failed restoration is reported as `ROLLBACK_FAILED`, never as success.

`run.sh` preserves the validated overlay on every normal update. Connect refuses a downgrade lacking the helper, templates, support marker or Caddy imports. Its rollback also includes the original public overlay. Manual `run.sh`, public changes and Connect source updates share `/var/lib/sovagrid/.public-web.lock`, outside updater snapshots; updater lock order is candidate lock then public lock. A supervising updater passes the internal `SOVAGRID_PUBLIC_WEB_LOCK_HELD=1` flag to its child installer to avoid a nested lock. Ordinary callers leave this flag unset.

Cancel or lost SSH does not imply that a server write did not happen. Connect must read `status` again and explicitly retry or disable the current generation. A disabled installation retains its managed directory and certificate/account storage for safe reuse. It reports `config:null`; unknown or changed files are never silently adopted.

Fixed error codes: `INVALID_REQUEST`, `UNMANAGED`, `SOURCE_UNTRUSTED`, `STATE_UNTRUSTED`, `STATE_CHANGED`, `ADDRESS_NOT_LOCAL`, `IPV6_UNAVAILABLE`, `PORT_BUSY`, `COMMAND_FAILED`, `LOCAL_UNHEALTHY`, `PUBLIC_UNHEALTHY`, `ROLLBACK_FAILED`, `BUSY`, `ROOT_REQUIRED`.

## Verification

Unit fixtures cover strict input, read-only preview, source/state compare-and-swap, immutable generations, interrupted apply repair, foreign/symlink/writable state, exact rollback, disable and actual shared locks. A verified Caddy binary exercises actual TLS routes against a real Hub: all Agent worker routes are denied before reaching Hub; browser API works; spoofed identity headers cannot evade login throttling; independent actual clients retain distinct identities. The local IPv6 loopback test demonstrates Caddy/Hub identity handling, not public Docker IPv6 support. The Docker CI fixture runs the validator alongside a live Web container holding static `.10`, checks the live CA remains unchanged, and publishes no host port. Production issuance and renewal readiness still require a reachable operator-configured address; a local fixture does not prove public CA validation.
