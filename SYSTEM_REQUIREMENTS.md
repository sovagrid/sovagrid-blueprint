# Требования к системе

Допуск к установке определяется возможностями системы, а не названием или версией дистрибутива. Источник требований — [platforms/requirements.json](platforms/requirements.json). `ID`, `VERSION_ID` и `ID_LIKE` не образуют список разрешённых ОС.

Изменения готовятся для следующего общего пакета после 1.0.0. Опубликованные архивы, bootstrap и приложения 1.0.0 сохраняют свои прежние байты и ограничения Ubuntu. Расширенный bootstrap нельзя публиковать с прежним закреплённым архивом: требования и сам серверный код обновляются согласованно.

## Hub и управляемый хост

Сам API Hub работает в Linux-контейнере с Python, хранит учётные записи и данные внутри собственной установки. Централизованная учётная запись SovaGrid для него не нужна. Требования к контейнерному процессу и требования к управлению ОС хоста — разные профили.

Текущий полный установщик устанавливает также локальный Agent, службы и привилегированные брокеры. Для этого профиля требуются:

- Linux и доступный procfs (`/proc/stat`, `/proc/meminfo`, `/proc/net/dev`, `/proc/self/fd`).
- Системный Python `/usr/bin/python3` версии 3.10 или новее.
- Работающий systemd не ниже 247; допускаются состояния `running` и `degraded`. Проверяется версия менеджера PID 1, а не только версия клиента `systemctl`.
- POSIX-пользователи и группы, UID/GID `root` равные 0, `/usr/sbin/nologin`, Unix-сокеты и права на системные каталоги.
- Bash 4+, команды GNU coreutils, util-linux и iproute2, доступный runtime журнала systemd.
- Локальный Docker с Linux-контейнерами (`/usr/bin/docker`, `unix:///var/run/docker.sock`) и работающий Compose plugin версии 2 или новее. Для SSH-возможностей — соответствующие клиент и сервер OpenSSH.

Системы без этих возможностей могут запускать отдельные контейнеры Hub при наличии совместимого контейнерного окружения; это не означает, что полный хостовый установщик и все локальные функции уже перенесены на Windows, macOS или OpenRC. Наличие одного Python недостаточно для установки системных брокеров.

## Подготовка зависимостей

Сначала проверяются уже доступные возможности. Если они есть, название дистрибутива и наличие APT не влияют на допуск. Неизвестная версия Ubuntu, Arch или другая система не отклоняются за имя.

Сейчас автоматическая установка недостающих пакетов реализована через APT. Если подходящего адаптера нет, установщик сообщает недостающие зависимости; он не вызывает чужой пакетный менеджер наугад. Это ограничение автоматической подготовки пакетов, а не белый список ОС.

Compose устанавливается из подходящего пакета либо из официального бинарника с закреплёнными версией и SHA-256 для поддерживаемой архитектуры. Уже установленный Docker не заменяется ради Compose. SELinux и другие защитные механизмы не отключаются: их политика должна разрешать требуемые контейнерные тома и Unix-сокеты.

## Клиенты и протокол

SSH-проверки до установки backend самодостаточны. Минимальные версии зависимостей согласуются в установщике, Connect, серверных helpers, Web и командах Apple/Android:

```sh
python3 tools/sync_platform_policy.py sync
python3 tools/sync_platform_policy.py check
```

Старый трёхполевой ответ Ubuntu и сохранённые журналы читаются для совместимости. Новый ответ содержит `distribution`, `version`, `python_version`, `systemd_version`. Название и версия ОС служат отображению; неизвестная ОС допускается при подходящих зависимостях. Отсутствующие метаданные заменяются нейтральными значениями. Неизвестные поля, некорректные значения и слишком старые зависимости отвергаются.

После изменения Connect runtime нужно сохранить его коммит и штатно синхронизировать закрытый vendor. После изменения Swift bootstrap требуется обновить reviewed blob и сверить скомпилированные команды Swift/Kotlin. Новые серверные архивы и клиентские pins выпускаются общим пакетом.

## Резервные копии

Копия данных Hub не зависит от названия ОС. Автоматический перенос полной хостовой копии — отдельный контракт `full/v2`: его существующие квитанции и восстановление пока реализованы для Ubuntu 22.04/24.04/26.04. Поэтому создание такой переносимой копии на другой ОС отклоняется до остановки служб или создания задания. Это ограничение переноса системной конфигурации, а не подключения хоста или работы Hub.

Обычный снимок управляемых файлов и резервное копирование базы Hub не объявляются автоматической миграцией системных служб между ОС.
